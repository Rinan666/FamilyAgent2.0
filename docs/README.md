# Docs 导航

> 版本：V1.1
> 用途：说明 docs 目录的分层结构、文档类型和维护约定
> 状态：Active
> 更新时间：2026-08-04

---

本目录按文档用途分层，避免产品文档、规划草稿、部署说明和学术材料混放。

## 目录说明

### `product/`
面向产品定位、当前能力、产品边界和演进方向的正式文档。

当前以单一主文档维护：
- `产品定位.md`：FamilyAgent 的详细产品定义、当前/部分完成/规划中能力状态和禁止过度表述的边界。

产品口径和能力状态优先更新这份主文档，避免重复维护分析、修订、矩阵和索引。只有职责真正独立、需要单独生命周期的专题才新增产品文档。

### `plans/`
规划、优化、演进方案类文档。

适合放：
- 迭代计划
- 功能扩展方案
- 阶段性优化方案
- 讨论中的设计草案

> 当前目录默认在 `.gitignore` 中忽略，适合放草稿和阶段性方案。

### `reference/`
边界清单、约束说明、专题参考材料。

适合放：
- 能力边界清单
- 风险说明
- 约束盘点
- 专题型参考文档

### `deployment/`
部署、运行、环境搭建相关文档。

适合放：
- docker 部署说明
- 本地/测试/生产环境启动说明
- 运维排查指引

### `academic/`
课程设计、毕业设计、学习材料、实验性写作等非产品主文档。

适合放：
- 课程设计文档
- 毕业设计草稿
- 学习笔记
- 非正式论文材料

> 当前目录默认在 `.gitignore` 中忽略，避免把学术材料与产品主文档混在一起。

---

## 文档管理约定

1. **项目主说明放根目录**
   仓库整体说明使用根目录 `README.md`，不再放在 `docs/README.md`。

2. **正式产品定义放 `docs/product/`**
   产品定位、当前能力状态、产品边界和演进方向统一维护在 `产品定位.md`。

3. **草稿计划放 `docs/plans/`**
   讨论中、可变动、阶段性的计划文档统一放这里。

4. **部署说明放 `docs/deployment/`**
   避免和产品需求文档混在一起。

5. **学术材料放 `docs/academic/`**
   与课程/答辩/论文相关的内容单独收拢。

---

## 推荐维护方式

- 更新产品定位、能力状态或产品边界：修改 `docs/product/产品定位.md`
- 新增真正独立的产品专题：确认无法并入产品主文档后再放 `docs/product/`
- 新增功能方案/优化方案：优先放 `docs/plans/`
- 新增边界/规则盘点：优先放 `docs/reference/`
- 新增部署和运维文档：优先放 `docs/deployment/`
- 新增课程、论文、学习笔记：优先放 `docs/academic/`
