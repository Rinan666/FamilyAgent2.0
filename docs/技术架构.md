# FamilyAgent 系统架构与接口契约

## 1. 文档范围

本文档只定义当前代码库中的系统分层、服务边界、通信路径和接口契约，不讨论产品愿景，不写泛化说明。接口定义以当前实现为准，主要对应：

- Java 后端：`backend/src/main/java/com/familyagent/module/**/controller`
- Python AI 服务：`ai-service/app/api/*.py`
- 前端调用层：`frontend/src/lib/api/*.ts`

## 2. 系统拓扑

```text
Browser
  -> Next.js Frontend
      -> Java Backend (/api/*)
      -> AI Proxy (/ai-proxy/*)

Java Backend
  -> PostgreSQL
  -> Redis
  -> RabbitMQ
  -> MinIO
  -> Python AI Service (/ai/*)

Python AI Service
  -> LLM Provider via LiteLLM
  -> PostgreSQL / pgvector（记忆相关能力）
```

## 3. 运行时分层

### 3.1 Frontend

- 责任：页面渲染、表单交互、会话流式展示、本地状态管理。
- 不负责：权限裁决、关系校验、记忆授权、AI 上下文裁剪。
- 外部契约：
  - 业务数据走 `/api/*`
  - AI JSON 与 SSE 走 `/ai-proxy/*`
  - Token 从 `localStorage.token` 读取，直接写入 `Authorization` 请求头

### 3.2 Java Backend

- 技术栈：Spring Boot 3.3、MyBatis-Plus、Sa-Token、Flyway。
- 责任：
  - 用户、家庭、成员、照护授权、日记、记忆、成长、会话等主业务
  - 统一鉴权与当前用户识别
  - 返回统一业务包结构
  - 对 AI 服务做受控代理
- 数据主权：
  - PostgreSQL 是结构化事实主库
  - Flyway 是唯一 schema 迁移来源

### 3.3 Python AI Service

- 技术栈：FastAPI、LiteLLM。
- 责任：
  - 家庭对话流式生成
  - 经验卡、保存规划、草稿整理、周摘要等 AI 能力
  - 输入治理、速率限制、并发限制、提示词与角色安全保护
- 不负责：
  - 家庭成员关系真值维护
  - 业务级资源授权裁决

## 4. 通信与鉴权契约

### 4.1 浏览器 -> Java Backend

- Header：`Authorization: <token>`
- Content-Type：`application/json`
- 响应包：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "requestId": "optional",
  "timestamp": 1710000000000
}
```

- 失败语义：
  - `code != 200` 视为业务失败
  - 前端收到 `401` 会清理本地 token 并跳转登录

### 4.2 浏览器 -> AI Proxy

- 前端固定请求 `/ai-proxy/*`
- Header：`Authorization: <token>`
- 普通 JSON 响应：

```json
{
  "success": true,
  "data": {}
}
```

- 失败响应：

```json
{
  "success": false,
  "detail": "error message"
}
```

- 状态码约定：
  - `400` 输入治理、角色劫持、提示词泄露等安全拦截
  - `413` 输入过长
  - `429` 速率限制，带 `Retry-After`
  - `504` 超时

### 4.3 Java Backend -> Python AI

- Java 侧通过 `AIServiceClient` 访问 Python `/ai/*`
- 聊天流接口由后端透传 `Authorization`
- 浏览器不直接访问 Python 原始地址，只通过 `/ai-proxy` 或 Java 代理暴露

### 7.2 FamilyAgent 流式聊天

对外入口有两层：

- 浏览器实际调用：`POST /ai-proxy/agent/chat/stream`
- Python 原始路由：`POST /ai/agent/chat/stream`

请求体契约：

```json
{
  "member_message": "string",
  "history": [{"role": "user", "content": "..." }],
  "subject": "FamilyAgent",
  "knowledge_point": "string",
  "memory_context": "string",
  "viewer_role": "MEMBER",
  "target_role": "MEMBER",
  "client_timestamp": "2026-06-11T00:00:00.000Z",
  "client_timezone": "Asia/Shanghai"
}
```

SSE 事件契约：

```text
: connected
data: {"content":"第一段回复"}
data: {"metadata":{"type":"metadata","...":"..."}}
data: {"content":"第二段回复"}
data: {"done":true}
```

错误事件：

```text
data: {"error":"message"}
```

前端处理规则：

- `content`：追加到回答正文
- `metadata`：作为 RAG / webSearch / 诊断元数据
- `done=true`：结束流
- `error`：结束并显示错误

## 8. 契约约束与兼容规则

- 浏览器只依赖前端 API 层，不直接拼装 Python 原始 URL。
- Java 后端返回统一 `Result<T>`，AI JSON 返回统一 `{ success, data }`。
- 流式聊天是唯一 SSE 契约，其它 AI 能力全部是 JSON。
- 权限裁决必须在 Java 后端完成，AI 服务只消费已裁剪上下文。
- 新增接口时必须同步更新三处：
  - controller / router
  - `frontend/src/lib/api/*`
  - `frontend/src/types/index.ts`

## 9. 当前最关键的接口边界

当前系统真正需要长期稳定的边界只有四条：

- `User/Family/Member`：身份与关系真值
- `Diary/Memory/Growth`：家庭内容主存储契约
- `Session/Agent Stream`：会话与流式交互契约
- `AI Memory Tools`：结构化 AI 输出契约

后续重构可以调整内部服务实现，但这四条边界不应轻易破坏。
