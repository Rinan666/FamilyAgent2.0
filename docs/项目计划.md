# 项目计划

## 当前阶段

**Phase 2：家族记忆与软资产传承 MVP 验证**

当前重点是完成战略校准和小范围验证：FamilyAgent 不再以题库和解题效率作为主竞争点，而是围绕家族日记、授权共享、家风价值观、长者经验、人生教训、成长守护和成员理解建立差异化价值。早期目标用户以有传承意识的中产家庭和喜欢记录的新生代用户为主，高净值/企业家家庭作为高端分支验证。

## 项目边界

Phase 2 只关注：

- 有传承意识家庭的软资产管理：家风、价值观、长者经验、人生教训和家庭沟通方式。
- 喜欢记录的新生代用户：日记、相册故事、自我复盘、父母长辈访谈和家庭记忆整理。
- 高净值或企业家家庭的高端分支：私有化部署、访谈整理、家族经验库和长期托管。
- 家族日记、重要事件、自我复盘和给家人的话。
- 日记与经验的可见范围：仅自己、全家、照护者。
- 家族经验、故事、提醒和长者建议的录入。
- 镜像 Agent：基于授权记录做风格参考、价值观参考和自我复盘辅助。
- AI 将家庭内容整理成经验卡、风险点、适用场景和行动建议。
- 成长守护作为结构化日记模板：体态、牙齿、视力、睡眠、运动、屏幕时间。
- 首页主线：家族日记、镜像 Agent、家庭提醒、长者建议和待跟进事项。
- 家庭成员角色、授权范围和未成年人数据保护。
- 家庭陪伴 AI、学习记录和错题作为成长观察信号来源。

Phase 2 暂不关注：

- 与成熟教育产品竞争海量题库。
- 复杂教材同步和大型诊断策略。
- 拍照答疑作为核心卖点。
- 医疗诊断或健康结论。
- 小程序、App 或大规模公开投放。
- 让普通用户围绕诊断、作业批改、错题本和学习报告建立主要使用习惯。

## 功能裁剪原则

当前采用“软裁剪”而不是硬删除：

- 侧栏和首页不再展示数学诊断、作业批改、错题本和学习报告。
- 相关路由、后端模型和 AI 能力暂时保留，避免破坏历史数据和依赖。
- 后续只有当这些功能能转化为家庭日记、成长守护或家庭陪伴 AI 的辅助信号时，才继续投入。
- 如果 10-30 个真实用户/家庭几乎不使用这些学习工具，下一轮再删除普通用户路由或合并到家庭陪伴 AI。

## 工程原则

- Java 负责业务、权限和持久化。
- Python 负责 AI 整理、总结、陪伴和风险提示。
- 前端负责家庭场景下的低门槛录入、展示和授权提示。
- 不让前端信任用户传入的 `userId`，以后端登录态和家庭成员关系为准。
- 家庭记忆、成员画像和未成年人数据进入 AI 前必须经过权限过滤。
- 家庭上下文进入 AI 前必须经过隐私守门；当前先使用规则版 PrivacyGuard，后续可增强为 Presidio。
- 记忆召回必须先由后端过滤家庭权限，再做文本或向量相关性排序，不能让 AI 服务直接全库检索。
- 镜像 Agent 不能声称自己是本人，不能代表真实想法，只能基于授权记录做参考。
- 有正式数据模型时不靠前端临时推断。
- 每次迭代优先修真实家庭遇到的最大阻塞。

## 本地测试种子

`scripts/seed-family003.sql` 提供一个完整五人家族，便于回归测试当前主线。

执行：

```powershell
docker cp scripts/seed-family003.sql fa-postgres:/tmp/seed-family003.sql
docker exec fa-postgres psql -U fa_user -d familyagent -f /tmp/seed-family003.sql
```

账号密码统一为 `Test@123456`。

| 用户名 | 昵称 | 家族身份 |
|--------|------|----------|
| `family003_grandpa` | 李明德 | `OWNER` |
| `family003_father` | 陈远航 | `ADMIN` |
| `family003_mother` | 林秋然 | `GUARDIAN` |
| `family003_aunt` | 陈知微 | `MEMBER` |
| `family003_student` | 陈一诺 | `STUDENT` |

种子家族包含：

- 9 条家族日记
- 6 条家族经验 / 记忆
- 3 条成长守护记录
- 1 条成长守护周报
- 5 条镜像画像
