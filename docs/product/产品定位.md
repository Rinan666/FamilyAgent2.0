## 1. 文档职责

本文档是 FamilyAgent 的详细产品定义和当前能力基线。根目录 `README.md` 提供简洁的项目入口；本文档负责说明产品为什么存在、当前代码能够做什么、哪些能力仍不完整，以及哪些内容只是后续方向。

本文档使用三种状态：

- **当前**：当前代码已经提供，实际可用范围仍受账号、家庭成员关系、权限、配置和外部服务状态约束。
- **部分完成**：底层能力已经存在，但覆盖范围、交互体验、质量或运维成熟度仍不完整。
- **规划中**：产品方向已经明确，但不能描述为当前能力。

历史实现记录、测试数量和具体迁移过程以 Git、CI、数据库迁移和发布记录为准。

## 2. 产品定位

FamilyAgent 是一个以**个人与家族真实人生经验**为基础的 AI 系统，具有两层核心价值：

- **对个人，它是决策与生活辅助工具**：帮助用户认识自己、理解处境，并从个人与家族成员经历过的选择、代价、结果和复盘中获得思考燃料、行动参考与可效仿的人生样本。
- **对家族，它是精神财富传承工具**：持续沉淀成员的真实经历、价值判断、处世经验和成长故事，使这些内容能够按权限共享、面向长期保存，并被当代成员与后人继续理解和调用。

FamilyAgent 不以提供脱离场景的人生道理为目标。它更关注：

- 当时处于什么环境。
- 面临哪些选择。
- 为什么作出某种判断。
- 为行动付出了什么代价。
- 最终产生了什么结果。
- 后来如何复盘。
- 这些经验与当前问题有哪些相似和不同。

系统可以结合授权记录提供有依据的倾向性建议，但不会替用户承担最终决定，也不会把家族经验包装成绝对正确答案。

---

## 3. 核心问题

FamilyAgent 重点解决三个问题：

1. **辅助决策与生活**  
   在迷茫、选择、关系和成长场景中，召回相似的个人与家族经历，说明哪些经验值得参考、哪些部分不能照搬。

2. **了解自己与家人**  
   通过持续积累的真实记录，帮助成员理解彼此的近况、价值排序、判断方式和成长变化。

3. **离线成员理解**  
   当真实成员不在线时，用户可以与其镜像对话，从授权资料中了解对方可能的视角和表达方式。

精神成员用于补充真实个人与家族经验之外的榜样和视角；记录整理、确认式保存、复盘提醒和 Action Agent 是长期积累的支撑能力，不是产品的第一定位。

## 4. 用户、账号与家庭范围

### 4.1 账号与注册

当前系统采用邀请制账号注册，并提供：

- 注册邀请码校验。
- 用户名和密码登录。
- 当前用户信息查询与资料维护。
- 密码修改与登录会话管理。
- 登录失败限制和禁用账号拦截。

需要区分两类邀请码：

- **注册邀请码**：允许一个人创建 FamilyAgent 账号。
- **家庭邀请码**：允许已经登录的用户加入某个家庭。

完成注册不会自动加入指定家庭。账号创建和家庭加入是两个独立步骤。

### 4.2 个人范围

用户可以在不向家庭公开的情况下维护个人记忆，并按需要选择：

- 仅自己可见。
- 向全部当前家庭共享。
- 向指定家庭共享。
- 向获得照护授权的成员开放。

### 4.3 家庭范围

当前家庭能力包括：

- 创建家庭并查看创建额度。
- 通过家庭邀请码加入家庭。
- 查看家庭和成员信息。
- 转移家庭所有权。
- 在强确认条件下删除家庭及其关联数据。
- 为其他家庭成员设置个人视角下的关系称谓。
- 授予或撤销日记、记忆、成长观察相关的照护访问权限。

当前有效的家庭权限层级主要是家庭所有者和普通成员。平台管理员是独立的系统级角色，不等同于家庭所有者。

当前没有完整产品入口支持成员主动退出家庭、家庭所有者移除单个成员或轮换家庭邀请码，因此这些能力不能描述为已实现。

## 5. 记录与经验库

### 5.1 统一记录底座

当前数据层已经将个人经历、家族经验、日记和成长观察收敛到统一记录与索引体系中。对用户而言，不同记录仍有不同用途和入口，但授权召回、来源追溯和向量索引建立在统一底座之上。

每条记录的可使用范围受以下因素影响：

- 记录所有者和家庭归属。
- 可见范围。
- 家庭成员关系。
- 照护授权。
- 记录状态和归档状态。

### 5.2 个人记忆库

当前支持：

- 创建和浏览个人记忆。
- 维护标题、内容和可见范围。
- 向全部家庭、指定家庭或照护授权成员共享。
- 在个人记忆工作台中归档记录。

个人记忆属于用户本人，不能因为加入家庭而自动变成全家可见内容。

### 5.3 家族记忆库

当前支持：

- 搜索和浏览可见记录。
- 编辑经过人工确认的内容。
- 修改可见范围。
- 归档与恢复。
- 对已归档记录执行永久删除。
- 在人工预览和确认后保存文言化改写。

家族记忆库聚合日记、家庭记忆和成长观察等来源，但来源类型仍会保留，供权限判断、回答依据和追溯使用。

### 5.4 值得沉淀的内容

内容是否值得保存不能只按“理性程度”或“是否包含观点”判断。以下内容都可能有长期价值：

- 成功与失败经历。
- 选择、代价、结果和复盘。
- 关系变化和生活阶段。
- 当时的情绪、事实与主观判断。
- 高价值灵感、方法和策略。
- 能体现个人差异、价值观或判断方式的表达。
- 帮助自己或家人理解近况的客观记录。

记录资格、长期洞见价值、召回相关性和共享资格是不同问题。客观或情绪化内容不应被自动视为低价值，只是在不同场景中的检索优先级可能不同。

## 6. Agent 对话与会话

### 6.1 当前对话目标

当前 Agent 页面支持在以下目标之间切换：

- **家庭 Agent**：结合用户和家庭范围内的授权经验提供回答。
- **真实成员镜像**：基于某位成员的授权记录模拟其可能的视角和表达方式。
- **精神成员**：依据用户维护的人设和材料提供补充视角。

当前前端仍提供 Quick 和 Think 两种响应模式：

- **Quick**：适合低延迟、直接回答，不进行家庭记忆召回，也不使用公共 Web Search。
- **Think**：可使用更丰富的授权召回，并在符合条件时查询公共网络信息。

这是当前交互方式，不是最终产品形态。后续方向是由系统根据用户意图自动决定回答深度、召回深度和联网策略。

### 6.2 持久会话

当前支持：

- 创建和持久化 Agent 会话。
- 自动保存用户和助手消息。
- 查看会话列表并恢复历史消息。
- 自动恢复最近的非空会话。
- 删除单个会话。
- 清理指定家庭的 Family Agent 会话。
- 在会话内切换对话目标并保留切换记录。
- 中止或丢弃正在进行的流式回答。

会话历史由应用保存并在请求时重新提供给模型，不代表 AI Provider 拥有独立、永久的会话记忆。

## 7. 授权召回、回答依据与联网

### 7.1 权限优先的 RAG

当前家庭召回遵循“先授权、后排序”的原则：

1. Backend 先检查家庭成员关系、可见范围和照护授权。
2. 只加载当前用户有权使用的候选记录。
3. 在授权候选中进行向量和文本混合排序。
4. Embedding 或向量检索异常时降级为文本召回。

召回来源可包括：

- 个人记忆。
- 家庭记忆。
- 日记。
- 成长观察。
- 镜像上下文所允许的材料。

### 7.2 回答依据

Think 模式的回答可以展示“回答依据”，包括：

- 使用的个人或家庭记录。
- 镜像相关授权材料。
- 公共 Web Search 来源。
- 召回模式和上下文说明。
- 资料不足提醒。

回答依据表示系统在生成回答时使用了哪些来源，不代表每一句生成文本都被来源逐字证明。模型仍可能进行归纳、推断或表达重组，因此界面和产品文案需要区分：

- 历史事实或原始记录。
- 个人与家族经验。
- 模型推断和建议。

### 7.3 受限公共 Web Search

当前 Web Search 具备以下边界：

- 只在 Think 模式启用。
- 仅处理用户明确要求联网，或答案依赖当前公开事实的请求。
- 保存记忆、家庭隐私、医疗照护记录、联系方式和地址类请求不会直接发送到公共搜索服务。
- 搜索 query 在外发前进行脱敏和公共化改写。
- 搜索依赖配置和 Provider 可用性；失败时会降级，而不是保证获得最新信息。

Web Search 不会把家庭私密记录当作公共搜索 query，也不构成正式事实核验或专业调查服务。

## 8. 镜像与精神成员

### 8.1 真实成员镜像

镜像模式可以根据授权的日记、记忆、成长观察和成员画像信息，帮助用户理解某位成员可能的：

- 表达方式。
- 价值排序。
- 判断习惯。
- 对某类问题的可能视角。

私密记录可以经过提炼形成风格参考，但不应向无权查看原文的用户暴露原始内容。

镜像模式的边界是：

- 它不是该成员本人。
- 它不是数字分身、意识延续或授权代表。
- 它不能替该成员作出现实承诺。
- 可用资料可能不完整、过时或有偏差。
- 当前聚合记忆库条目并未全部直接接入镜像返回结构，不能描述为对全部家庭资料的完整还原。

### 8.2 精神成员

精神成员用于补充真实个人和家族经验之外的榜样与视角。当前支持：

- 家庭成员查看和选择精神成员。
- 家庭所有者创建、编辑和删除精神成员。
- 每个家庭最多维护 3 个精神成员。
- 家庭所有者维护精神成员材料卡。
- 粘贴长文本，由 AI 生成可编辑的人设和材料草稿。
- 在 Agent 页面选择精神成员进行对话。

AI 材料整理只生成草稿，不直接持久化；家庭所有者需要检查并分别保存人设和材料。

精神成员会尽可能依据设定和材料保持一致，但不是权威导师、事实真人，也不能保证完全复现某个历史人物或思想体系。

## 9. AI 整理、保存与行动支撑

### 9.1 当前保存流程

当前保存能力是**用户明确触发的确认式流程**：

1. 用户明确表达保存意图。
2. AI 判断内容是否适合保存，并生成保存计划或可编辑草稿。
3. 用户检查并修改保存类型、标题、正文、标签、可见范围和目标家庭。
4. 用户确认保存或取消。
5. Backend 写工具再次执行权限和确认策略。
6. 写入过程记录 tool call、confirmation、run、SkillRun、审计和来源关联。

当前可保存为：

- 日记或家庭记录。
- 个人记忆。
- 家庭记忆。
- 成长观察。

AI 可以拒绝明显不适合持久化的内容；AI 草稿失败时，前端可以使用原始文本生成可编辑降级草稿。

### 9.2 当前不具备的自动性

普通聊天完成后，系统不会自动扫描每一轮对话并主动弹出保存建议，也不会在后台自主写入长期记录。

以下能力仍属于规划方向：

- 未经明确保存指令的主动价值发现。
- 主动保存建议和周期复盘提醒。
- 跨会话、跨天执行的长期任务。
- 用户可见的多步骤任务工作台、恢复和重试。

### 9.3 Action Agent 定位

Action Agent 应优先服务于：

- 内容整理。
- 草稿生成。
- 确认式保存。
- 复盘和提醒。
- 可追溯的辅助操作。

它不是通用家庭事务执行器，也不应绕过用户确认或 Backend 权限直接改变家庭数据。

## 10. 平台管理与诊断

平台管理员拥有独立于家庭所有者的管理入口。当前数据库管理页面支持：

- 查看数据库和 pgvector 状态。
- 查看用户、家庭、成员、关系、照护授权、记录、Embedding、会话、归档和 SkillRun 等数量摘要。
- 查看失败的 Embedding 和 SkillRun。
- 查看会话存储与归档诊断。
- 搜索和分页查看用户、家庭及家庭成员。
- 查看单个家庭的记录、运行和 Embedding 健康摘要。
- 以经过校验的家庭成员身份执行 RAG 召回诊断。
- 在多重确认后删除用户及关联数据。

这些是平台运维和诊断能力，不是家庭所有者的日常产品权限。诊断界面以摘要为主，但 RAG 诊断可能展示来源标题和片段，因此属于受限的高权限访问。

## 11. 安全、隐私与运行边界

当前代码已经建立生产导向的安全基线：

- 除注册、登录和公开健康检查外，Backend API 默认要求登录。
- 家庭数据操作经过成员关系、角色、记录可见性和照护授权检查。
- 家庭所有者权限与平台管理员权限分离。
- Backend 是家庭数据、权限、召回、写入、确认、审计和 provenance 的业务权威。
- Frontend 不能通过普通 AI proxy 绕过 Backend 调用 Agent、记忆、家庭和保存工具。
- Python AI Service 的 Backend-owned 能力要求内部服务身份。
- 普通调用方提供的 `memory_context` 不能成为可信家庭上下文。
- 发送给外部 Embedding、LLM 或 Web Search 前会执行轻量隐私脱敏和输入安全检查。
- AI 调用受到输入大小、输出 token、并发、速率和超时限制。
- 生产配置会拒绝已知开发默认密钥或缺少必要密钥的启动方式。
- 生产 Compose 通过内部网络连接数据库、缓存、消息队列、对象存储、Backend 和 AI Service，并通过受控入口暴露前端。

这些能力不等于合规认证、专业渗透测试结论或绝对安全保证。当前隐私识别主要依赖规则，AI Service 的部分限流和并发状态为进程内状态，仍需要持续的运维、备份、恢复演练和安全审计。

## 13. 产品边界与禁止表述

正式产品说明不应宣称：

- FamilyAgent 可以替用户作出最终决定。
- 家族经验必然正确、完整或适用于当前处境。
- 镜像等同于真实成员本人或延续其身份。
- 精神成员能够完全忠于某个真人、历史人物或思想体系。
- 系统会自动保存所有高价值内容。
- 家庭数据默认无限制共享。
- 回答依据等同于对每句话的事实证明。
- Web Search 一定提供最新或权威信息。
- 系统已经完整、无偏差地理解某个人。
- 照护授权等同于医疗、监护或专业照护系统。
- 当前安全措施代表合规认证或零风险生产环境。
- 数据能够在没有备份、运维和账号生命周期保障的情况下永久存在。

## 14. 产品演进方向

后续演进遵循以下顺序：

1. 保持一个统一 AI 对话入口，通过自然语言切换家庭上下文、真实成员镜像和精神成员。
2. 取消要求用户选择 Quick / Think，由系统根据意图决定回答深度、召回深度和联网策略。
3. 使用统一记录进行全局授权召回，不再按日记、记忆和成长观察分配固定召回名额。
4. 为决策场景提供更稳定、可追溯的参考结构：处境、选择、代价、结果、复盘以及与当前问题的差异。
5. 增强近况流、阶段摘要和个人/成员画像，但保留来源、时间和不确定性。
6. 在用户同意和可撤销的前提下增强主动发现、复盘提醒和保存建议。
7. 只有在出现可恢复长任务的真实需求后，才建设长期任务工作台、调度和跨天恢复。
8. 持续加强监控、备份恢复、安全审计和真实 Provider 质量评测。

## 15. 当前阶段最准确的定义

> FamilyAgent 是一个以个人与家族真实人生经验为基础的 AI 决策、生活辅助和精神财富传承系统。它通过权限化记录、授权召回、回答依据、真实成员镜像、精神成员和确认式 AI 整理，帮助用户理解自己与家人，并从真实处境、选择、代价、结果和复盘中获得可追溯的参考；最终决定仍由用户作出。
