# FamilyAgent 用户使用与 PMF 落地计划

**版本**：v0.1  
**日期**：2026-06-05  
**阶段**：Phase 1 AI 家教 MVP 公网试用与 PMF 验证  
**目标周期**：30 天  

---

## 1. 目标

当前项目已经具备 AI 家教 MVP 的核心雏形，但还没有被真实用户持续使用。本文档的目标是把项目从“本地可运行”推进到“种子用户可访问、可试用、可反馈、可判断 PMF”的状态。

30 天内不追求大规模增长，核心目标是验证：

1. 目标家庭是否愿意打开并完成首次体验。
2. 学生是否愿意重复使用 AI 家教做数学练习。
3. 家长是否能从报告中感知价值。
4. 用户是否愿意推荐或付费。

---

## 2. 推荐产品形态

第一阶段推荐形态：

> 微信可打开的邀请制 Web Beta。

用户使用路径：

```text
微信群 / 私聊 / 老师推荐
  -> 打开 FamilyAgent Web 链接
  -> 输入邀请码
  -> 注册或登录
  -> 选择孩子年级
  -> 完成数学诊断
  -> 进入 AI 家教讲题
  -> 家长查看学习报告
```

暂不建议第一阶段做 App 或小程序。原因：

- 当前项目已是 Next.js Web 应用，H5 链接最快可用。
- 微信内直接打开网页即可完成内测。
- App / 小程序会引入审核、发布、账号体系和适配成本，容易拖慢 PMF 验证。
- PMF 阶段最重要的是用户行为和反馈，不是渠道形态完整度。

---

## 3. 目标用户

第一阶段只聚焦一个窄人群：

> 初一 / 初二学生 + 数学基础不稳 + 家长希望低成本获得陪练和讲题支持。

面向用户的话术建议：

> AI 数学陪练内测版：每天 15 分钟，诊断薄弱点，AI 陪孩子一步步解题，家长能看到学习报告。

不要在第一阶段强调“家族教育平台”“镜像 Agent”“长期家族知识库”等完整愿景。这些是长期战略，但种子用户只关心孩子当前学习有没有帮助。

## 4. 用户入口设计

### 4.1 对外入口

推荐准备一个统一入口：

```text
https://familyagent.example.com
```

如果尚未完成正式部署，可先用临时公网隧道：

```text
https://xxx.trycloudflare.com
```

入口页面必须聚焦一个动作：

> 免费完成一次数学诊断。

不要做复杂落地页，不要把第一屏变成产品介绍。PMF 阶段用户需要尽快进入体验。

### 4.2 注册方式

推荐使用邀请制注册：

- 每个种子家庭一个邀请码。
- 邀请码与渠道绑定，例如 `TEACHER_A_001`、`PARENT_GROUP_001`。
- 注册时记录邀请码来源。
- 邀请码可限制次数，避免公网链接被未知用户滥用。

### 4.3 测试账号

准备一个演示账号，供老师、家长、合作方快速体验。

建议格式：

```text
账号：demo-parent@example.com
密码：由项目负责人线下提供
角色：家长
内置学生：初一学生
```

演示账号只用于展示，不用于收集真实学习数据。

## 5. 部署落地方案

### 5.1 临时内测方案：公网隧道

适用场景：

- 1-3 天内快速让 5-10 个家庭试用。
- 项目仍主要运行在开发电脑。
- 需要快速验证交互流程。

推荐方式：

```powershell
.\start-all.bat
cloudflared tunnel --url http://localhost:3000
cloudflared tunnel --url http://localhost:8000
```

注意事项：

- 前端如果仍直连 AI 服务，必须把 `NEXT_PUBLIC_AI_SERVICE_URL` 配置成 AI 服务的公网隧道地址。
- Java 后端可以继续由 Next.js `/api/*` 代理到本机 `localhost:8080`。
- 开发电脑必须保持开机，服务窗口不能关闭。
- 临时隧道地址可能变化，每次变化后需要更新前端配置并重启前端。

临时方案只适合小范围体验，不适合持续公开 Beta。

### 5.2 推荐 Beta 方案：云服务器单机部署

适用场景：

- 连续 2-8 周验证 PMF。
- 用户数量 20-200。
- 需要稳定访问、日志、备份和排查能力。

推荐架构：

```text
用户浏览器
  -> Nginx HTTPS :443
      /      -> Next.js frontend :3000
      /api/* -> Java backend :8080
  -> Java backend
      -> Python AI service :8000
  -> PostgreSQL / Redis / RabbitMQ / MinIO
```

关键原则：

- 公网只暴露 Nginx 443。
- 前端只访问同域名 `/api/*`。
- Python AI 服务尽量不直接暴露公网。
- Java 后端统一处理鉴权、权限、限流、会话记录和成本统计。

### 5.3 生产前建议架构优化

当前项目存在“前端直连 AI 服务”的设计。PMF 临时内测可接受，但公开 Beta 建议逐步改成：

```text
Browser
  -> Next.js frontend
  -> Java /api/tutor/stream
  -> Python /internal/tutor/stream
```

Java 负责：

- 用户登录态校验。
- 家庭和学生权限校验。
- 会话创建与持久化。
- 限流和防刷。
- 调用 Python AI 服务。
- 转发 SSE 流式响应。
- 记录 token 成本和学习行为。

Python 负责：

- TutorAgent。
- GraderAgent。
- GeneratorAgent。
- sympy 数学验证。
- BKT 计算。

## 6. MVP 必备用户流程

为了让用户真正完成体验，而不是只打开页面，建议 Beta 首屏流程如下：

```text
注册 / 登录
  -> 选择学生年级
  -> 5-10 道数学诊断题
  -> AI 家教讲解其中 1-2 道错题
  -> 生成家长报告
  -> 推荐下一次练习
```

### 6.1 学生端关键体验

学生需要感受到：

- 不会做题时，AI 不是直接给答案，而是一步步提示。
- 回答错了不会被批评，而是被引导发现错误。
- 练习量不大，15 分钟内能完成一次有效体验。
- 每次回来都有明确下一题或下一组任务。

### 6.2 家长端关键体验

家长需要感受到：

- 知道孩子哪里薄弱。
- 知道今天有没有认真练。
- 知道下一步该练什么。
- 能看到比“分数”更具体的学习过程。

家长报告建议包含：

```text
本次练习时长
完成题目数量
正确率
薄弱知识点
典型错误
AI 家教建议
下一次推荐练习
```

## 7. PMF 指标

不要用注册数判断 PMF。注册数只能说明有人好奇，不说明用户需要。

第一阶段建议看这些指标：

| 指标 | 说明 | 目标 |
|---|---|---|
| 注册转化率 | 打开链接后完成注册的人数占比 | 30%+ |
| 激活率 | 注册后完成首次诊断的人数占比 | 60%+ |
| 首次价值达成率 | 完成一次 AI 讲题或错题纠正的人数占比 | 40%+ |
| 次日留存 | 第二天再次使用的人数占比 | 20%+ |
| 7 日留存 | 第 7 天仍有使用行为的人数占比 | 10%+ |
| 周练习深度 | 每个学生每周完成题目数 | 20+ |
| 家长报告查看率 | 家长查看报告的人数占比 | 50%+ |
| 主动反馈数 | 用户主动提出问题、建议或追问 | 10 条+ |
| 付费意愿 | 愿意付费或询问价格的家庭占比 | 10%-20% |

PMF 问卷建议在使用 7-14 天后发送：

> 如果以后不能继续使用 FamilyAgent AI 数学陪练，你会有多失望？

选项：

1. 非常失望。
2. 有点失望。
3. 不失望。
4. 我没有真正使用过。

如果“非常失望”接近或超过 40%，可以认为有较强 PMF 信号。

## 8. 30 天执行计划

### 第 1 周：公网可用与闭环打通

目标：

- 用户能通过一个链接访问项目。
- 注册、登录、诊断、AI 家教、报告形成完整闭环。
- 内部完成 3-5 次端到端演练。

任务：

- 部署临时公网隧道或云服务器 Beta 环境。
- 配置 HTTPS。
- 准备邀请码机制。
- 准备演示账号。
- 确认前端、Java 后端、Python AI 服务公网链路可用。
- 修复跨域、鉴权、SSE、环境变量问题。
- 加入最小埋点日志。

验收标准：

- 一个新用户可以在 15 分钟内完成首次体验。
- 负责人可以在后台或日志中看到用户完成了哪些关键动作。

### 第 2 周：10-20 个家庭试用

目标：

- 找到第一批真实种子用户。
- 每天观察使用问题。
- 收集具体反馈，而不是泛泛评价。

任务：

- 邀请 10-20 个目标家庭。
- 每个家庭分配邀请码。
- 建立一个用户反馈表。
- 每天查看注册、诊断、AI 对话和报告查看数据。
- 对 3-5 个家庭做访谈。

重点问题：

- 用户是否知道第一步该做什么？
- 孩子是否愿意继续做题？
- AI 讲解是否有帮助？
- 家长是否看得懂报告？
- 哪一步流失最高？

### 第 3 周：修最痛的 3 个问题

目标：

- 不做大改版，只修影响用户完成闭环的关键问题。

常见优先级：

1. 注册和登录太麻烦。
2. 首次进入不知道做什么。
3. 题目难度不合适。
4. AI 讲解太长或太像直接给答案。
5. 数学公式渲染或移动端显示有问题。
6. 家长报告没有足够价值。
7. SSE 中断或响应太慢。

验收标准：

- 第二批用户的激活率明显高于第一批。
- 用户反馈从“不能用 / 不知道怎么用”转向“希望增加某些能力”。

### 第 4 周：扩大到 50 个家庭并测试付费

目标：

- 验证复用和付费意愿。
- 判断是否值得进入下一阶段。

任务：

- 扩大到 50 个目标家庭。
- 增加 7 天使用提醒。
- 测试轻量付费表达，例如：
  - 19 元 / 7 天体验。
  - 99 元 / 月 AI 数学陪练。
  - 老师班级试点套餐。
- 发 PMF 问卷。
- 汇总数据和访谈。

判断标准：

```text
继续推进：
- 50 个家庭中，15-20 个学生有重复使用。
- 5-10 个家长主动追问、推荐或表达付费意愿。
- 用户反馈集中在“怎么更好用”，而不是“为什么要用”。

需要调整：
- 注册不少，但完成诊断很少。
- 完成一次体验后几乎无人回来。
- 家长看不懂报告或不觉得有价值。
- 学生觉得 AI 讲解像普通答案生成器。

考虑转向：
- 目标用户不愿为数学陪练付费。
- 老师端/家长端价值明显强于学生端。
- 用户更想要作业批改、错题本或诊断报告，而不是 AI 对话家教。
```

优先级从高到低：

1. 身边有初中孩子的家庭。
2. 数学老师或教培老师推荐的学生。

5. 与 1-2 位老师合作做课后 AI 陪练试点。


## 10. 风险与保护

### 10.1 未成年人数据

必须遵守数据最小化原则：

- 不收集与学习无关的敏感信息。
- 不要求学生上传真实身份证明。
- 家长知情并同意孩子使用。
- 学习数据只用于产品改进和学习报告。
- 提供删除账号和删除数据的入口或人工处理机制。

### 10.2 AI 输出安全

AI 家教场景要避免：

- 给出不确定却肯定的数学结论。
- 引导学生输入隐私。
- 生成不适合未成年人的内容。
- 替学生完成作业而不讲过程。
- 长时间诱导使用。

生产前建议：

- 关闭 AI 服务鉴权 fail-open。
- 给 AI 接口加限流。
- 记录 AI 响应错误和人工抽查样本。
- 对公开接口加入内容安全检查。

### 10.3 成本风险

AI 调用需要控制成本：

- 每个邀请码限制每日使用次数。
- 每个学生限制每日 AI 对话轮次。
- 对长对话进行摘要或截断。
- 记录每次请求 token 使用量。
- 对异常频繁请求自动限流。

## 12. 最小上线标准

在邀请第一批用户之前，至少满足：

```text
1. 用户能通过公网链接打开项目。
2. 用户能注册或登录。
3. 用户能完成一次数学诊断。
4. 用户能收到 AI 家教讲解。
5. 家长能看到一份简单报告。
6. 项目负责人能看到关键使用数据。
7. 异常用户无法无限刷 AI 接口。
```

如果以上条件不满足，不建议对外发链接，否则反馈会集中在可用性问题，无法判断 PMF。

#### 第二步：增加邀请码注册

目标：

> 只有拿到邀请码的种子用户可以注册，并且能统计用户来源。

最小实现，不需要先做复杂后台：

1. 后端增加一张邀请码表。
2. 注册请求增加 `inviteCode` 字段。
3. 注册时校验邀请码是否存在、是否启用、是否超过使用次数。
4. 注册成功后记录邀请码使用次数。
5. 用户表或单独日志表记录该用户来自哪个邀请码。

建议数据表：

```sql
CREATE TABLE invite_codes (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(64) NOT NULL UNIQUE,
    channel VARCHAR(100),
    max_uses INT NOT NULL DEFAULT 1,
    used_count INT NOT NULL DEFAULT 0,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    expires_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

当前代码改动点：

- 前端类型：`frontend/src/types/index.ts` 的 `RegisterRequest` 增加 `inviteCode?: string`。
- 前端页面：`frontend/src/app/(auth)/register/page.tsx` 增加邀请码输入框，并提交给 `userApi.register`。
- 后端 DTO：`backend/src/main/java/com/familyagent/module/user/dto/RegisterRequest.java` 增加 `inviteCode` 字段。
- 后端服务：`backend/src/main/java/com/familyagent/module/user/service/UserService.java` 的 `register` 中增加邀请码校验。

验收：

- 没有邀请码不能注册。
- 错误邀请码不能注册。
- 已用完的邀请码不能注册。
- 有效邀请码可以注册。
- 能查到每个邀请码带来了哪个用户。

#### 第三步：将新用户路径改为诊断优先

目标：

> 新用户不要进入空 Dashboard，而是直接开始一次数学诊断。

当前代码里：

- 首页 `frontend/src/app/page.tsx` 会跳转到 `/dashboard`。
- 登录成功后 `frontend/src/app/(auth)/login/page.tsx` 会跳转到 `/dashboard`。
- 注册成功后跳到 `/login?registered=true`。

建议改成：

```text
新用户注册成功
  -> 自动登录或跳登录页
  -> 登录成功后进入 /dashboard/test
```

最小改法：

1. 把登录成功后的跳转从 `/dashboard` 改为 `/dashboard/test`。
2. 把首页从 `/dashboard` 改为 `/dashboard/test`。
3. Dashboard 首页保留，但不作为新用户第一入口。

更好的改法：

1. 用户表增加 `onboardingCompleted` 或用后端接口判断是否有测评记录。
2. 登录后如果没有测评记录，跳 `/dashboard/test`。
3. 如果已有测评记录，跳 `/dashboard/tutor` 或 `/dashboard`。

建议第一阶段先做最小改法。PMF 阶段要减少用户犹豫，不要让用户自己选功能。

验收：

- 用户登录后直接看到诊断题或开始诊断按钮。
- 15 分钟内可以完成诊断。
- 完成诊断后能进入 AI 讲解或报告。

#### 第四步：准备 10 个真实家庭试用

目标：

> 拿到第一批真实行为数据和访谈反馈。

准备清单：

1. 10 个邀请码。
2. 一个用户登记表。
3. 一个反馈表。
4. 一个微信群或私聊跟进方式。
5. 一段固定邀约文案。
6. 一份试用说明。

用户登记表字段：

```text
家庭编号
邀请码
来源
孩子年级
数学状态：偏弱 / 中等 / 较好
家长联系方式
是否完成注册
是否完成诊断
是否完成 AI 讲题
是否查看报告
是否愿意继续使用
是否愿意付费
备注
```

反馈表问题：

```text
1. 孩子是否能独立完成首次使用？
2. 哪一步最卡？
3. AI 讲解是否有帮助？
4. 题目难度是否合适？
5. 家长报告是否看得懂？
6. 你还希望它解决什么问题？
7. 如果每月 99 元，你是否愿意继续使用？
```

发给家长的试用说明：

```text
请让孩子独立使用 15 分钟：
1. 打开链接。
2. 输入邀请码注册。
3. 完成数学诊断。
4. 选择一道不会的题，让 AI 家教一步步讲。
5. 家长最后看一下学习报告。

试用后请告诉我：哪一步最不顺、AI 讲解有没有帮助、是否愿意下次继续用。
```

验收：

- 10 个家庭中至少 7 个完成注册。
- 至少 5 个孩子完成诊断。
- 至少 3 个家庭给出具体反馈。

#### 第五步：每天根据真实使用数据修一个最影响闭环的问题

目标：

> 每天只修最影响用户完成闭环的问题，不做发散式大改版。

每天固定节奏：

```text
上午：看前一天数据和错误日志。
中午：选出今天唯一 P0 问题。
下午：修复并部署。
晚上：请 1-2 个用户重新试。
```

每天必看数据：

```text
打开链接人数
注册人数
完成诊断人数
完成 AI 讲题人数
报告查看人数
第二天回访人数
AI 接口错误数
平均响应时间
用户主动反馈
```

问题优先级判断：

```text
P0：导致用户无法完成首次体验的问题。
P1：用户能完成，但体验明显不顺的问题。
P2：锦上添花的问题。
```

第一周最常见 P0：

- 手机打不开链接。
- 注册失败。
- 登录后不知道点哪里。
- 诊断题加载失败。
- AI 响应失败或太慢。
- 数学公式显示错乱。
- 移动端按钮/文字重叠。

每日复盘模板：

```text
日期：
今日新增用户：
完成诊断人数：
完成 AI 讲题人数：
最大流失点：
用户原话反馈：
今天修复的问题：
明天只修一个问题：
是否出现付费/推荐信号：
```

30 天内的原则：

- 不追求功能多。
- 不同时改 5 个方向。
- 不用注册数安慰自己。
- 每天只问：更多孩子是否顺利完成了一次有价值的学习体验。
