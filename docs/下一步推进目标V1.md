# 下一步推进目标 V1

**日期**：2026年6月4日  
**阶段**：Phase 1 — AI家教 MVP 内化与闭环完善  
**目标**：把已有 AI家教能力从“功能可运行”推进到“稳定、可评估、可持续学习”的 MVP 形态。

---

## 一、总体方向

下一步不优先扩展 Growth、Mirror、多模态或语音，而是先内化和完善已有 AI家教功能。

核心闭环：

```text
题库充实
  -> 独立测试模块解析测评要求
  -> 生成测试内容
  -> AI批改
  -> BKT学力更新
  -> 个性化讲题
  -> 会话/学习记忆沉淀
  -> 下一轮自适应练习
```

阶段目标是让 AI家教不只是“讲一道题”，而是能持续了解孩子的知识薄弱点、讲题偏好、学习表现，并据此调整教学。

---

## 二、P0 优先级

### P0.1 充实数学测试题库

当前题库数量不足，会限制学力评估、错题本、自适应抽题和测试模式的真实效果。

近期目标：

- 覆盖初中数学核心知识点。
- 每个重点知识点至少有多道题。
- 包含难度 1-5 的梯度。
- 题目应包含题干、答案、步骤、解析。
- 题目能够产生真实的答题差异，便于形成错题记录和 BKT 变化。

### P0.2 设计独立测试模块

测试功能不应继续放在 AI家教对话窗口里。讲题窗口适合讲题和追问，但“测试模式下用户直接在聊天输入框里输入答案”不符合正式测评体验。

新的产品边界：

- **讲题模块**：保留在对话窗口中，支持引导式讲题和快速答案式讲题。
- **测试模块**：从对话窗口中分离，成为独立功能模块。
- **错题本**：承接测试结果和复习，不作为测试入口的主体。

目标流程应调整为：

```text
用户提出测试要求
  -> AI/规则解析题目数量、范围、难度、题型
  -> 从题库抽题或 AI 生成题目
  -> 生成测试内容
  -> 输出为页面文本、PDF 或其他文件格式
  -> 学生完成测试
  -> AI批改
  -> 生成测试记录
  -> 更新 BKT
  -> 展示薄弱点
  -> 推荐下一组题
```

当前代码已有题库、批改、学力档案和错题本基础，但测试仍与家教对话窗口耦合。下一步应先设计独立测试模块的数据结构和交互方式，再把“提交测评结果”和“BKT 写回”前后端联通。

测试要求解析示例：

```json
{
  "subject": "数学",
  "grade": "初中",
  "knowledge_scope": ["一元一次方程", "一元一次不等式"],
  "difficulty": 3,
  "question_count": 10,
  "question_types": ["CALCULATION", "CHOICE"],
  "output_format": "pdf"
}
```

测试内容输出形式：

| 输出形式 | 说明 |
|----------|------|
| 页面文本 | 适合在线答题和即时批改 |
| PDF 文件 | 适合打印、离线完成或正式测评 |
| 结构化 JSON | 适合前端渲染、保存测试记录、后续批改 |
| 其他文件 | 未来可扩展为 Word、图片试卷或小程序分享格式 |

### P0.3 明确两种讲题风格

AI家教至少支持两种风格：

| 风格 | 标识 | 说明 |
|------|------|------|
| 引导式讲题 | `guided` | 苏格拉底式提问，不直接给答案，引导学生思考 |
| 快速答案式 | `direct` | 直接给出答案、步骤、关键方法和注意点 |

近期目标：

- 前端提供显式切换。
- 请求中携带 `teaching_style`。
- AI Prompt 根据风格切换讲题策略。
- 默认使用引导式讲题。

## 三、P1 优先级

### P1.1 基础会话记忆

AI家教应先具备最基础的“不失忆”能力：

- 当前题目上下文。
- 当前对话历史。
- 该知识点掌握程度。
- 学生当前更偏好的讲题风格。

后续再扩展到长期学习风格、性格特征和 Mirror Agent 记忆。

### P1.2 错题本数据联动

错题本不是 Phase 1 的主线功能，但应自然承接测评数据：

```text
AI批改判错
  -> test_records 记录结果
  -> wrong questions 可查询
  -> 错题本显示
  -> 点击重新练习
```

当前错题本前端页面已经存在，下一步重点是让真实测试数据流入。

### P1.3 会话历史可用

AI家教应能保存和查看历史对话：

- 一道题对应一段讲解记录。
- 用户可以查看历史讲题。
- 后续可用于学习记忆和个性化推荐。

## 四、P2 优先级

### P2.1 前端关键测试

优先保护以下逻辑：

- `api.ts` 请求封装。
- `authStore` 登录/退出状态。
- `chatStore` 流式消息追加。
- Tutor 页面讲题风格切换。
- 批改结果渲染。

### P2.2 AI 输出质量兜底

需要逐步建立 AI 输出约束：

- 引导式模式不直接给最终答案。
- 快速答案式模式允许直接给答案，但要结构清楚。
- 批改结果必须稳定返回结构化 JSON。
- 出题结果必须包含答案和步骤。
- 数学正确性尽量由 sympy 或确定性规则验证。

### P2.3 异常和空状态体验

需要完善：

- AI 服务不可用。
- 后端鉴权失败。
- 没有题库。
- 没有学力数据。
- SSE 中断。
- 批改返回格式异常。

---

## 五、本轮代码推进范围

本轮优先做两项低风险、高收益改动：

1. **讲题风格链路落地**
   - 前端新增“引导式 / 快速答案式”切换。
   - 请求体新增 `teaching_style`。
   - Python AI 服务接收该字段。
   - TutorAgent 根据该字段构建不同 Prompt。

2. **补充数学种子题库**
   - 在数据库初始化脚本中加入更多初中数学题。
   - 覆盖方程、不等式、整式、几何、函数等知识点。
   - 为抽题、测试模式、错题本和学力评估提供更真实的数据基础。

暂不在本轮一次性新增完整测评提交接口，避免同时改动前端、后端、数据库写入和 BKT 流程导致风险过大。

---

## 六、验收标准

本轮完成后应满足：

- 前端 AI家教页可以切换讲题风格。
- `guided` 模式保持引导式教学。
- `direct` 模式可以直接给出答案、步骤和总结。
- AI 服务请求模型支持 `teaching_style`。
- 数据库初始化后题库不再只有少量示例题。
- 文档明确后续 P0/P1/P2 推进顺序。
