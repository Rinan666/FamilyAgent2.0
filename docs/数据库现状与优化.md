# 数据库现状与优化

## 当前情况

FamilyAgent 当前使用 PostgreSQL 16 作为主数据库，并启用 pgvector 存储家族记忆的向量索引。Redis、RabbitMQ、MinIO 已在 `docker-compose.yml` 中配置，其中 Redis 主要服务登录态和缓存，RabbitMQ 暂未作为主流程依赖，MinIO 用于后续照片、语音、附件等对象数据。

目前数据库里有两类表：

- 核心表：`users`、`families`、`family_members`、`family_relationships`、`care_authorizations`、`diary_entries`、`memory_entries`、`growth_guard_records`、`growth_guard_reports`、`memory_embeddings`、`mirror_agent_data`、`heritage_tasks`、`chat_sessions`。
- 历史教育表：`questions`、`knowledge_points`、`test_records`、`wrong_question_records`、`ability_profiles` 等。这些来自早期 AI 家教方向，当前不再是产品主线，建议先归为 legacy/archive，等核心家族记忆闭环稳定后再清理。

当前 schema 来源也分两层：

- `scripts/init-db.sql`：Docker 首次创建 PostgreSQL volume 时执行，包含早期基础表和种子数据。
- Java `*SchemaInitializer`：后端启动时补齐新表、字段和索引，适合当前 MVP 快速演进，但长期建议迁移到 Flyway 或 Liquibase。

## 本次优化

本次没有删除任何业务数据，只做结构性修正和索引补强：

- 修复 `memory_embeddings.source_type` 约束，允许 `DIARY`、`MEMORY`、`GROWTH_OBSERVATION`。此前成长观察会被代码送去建向量索引，但数据库旧约束只允许日记和经验，可能导致成长观察无法进入 RAG。
- 为 `memory_embeddings` 增加家族、状态、来源、更新时间相关索引，优化授权召回和向量排序前的候选过滤。
- 为 `diary_entries` 增加家族可见性分页、家族成员记录、关联成员检索索引。
- 为 `memory_entries` 增加家族经验列表、类型过滤、日记沉淀去重查询索引。
- 为 `growth_guard_records` 和 `growth_guard_reports` 增加家族、目标成员、状态、时间维度索引。
- 为 `care_authorizations` 增加 ACTIVE 授权判断索引，优化日记、成长观察、经验召回时的权限过滤。
- 为 `heritage_tasks` 增加家族任务列表索引。

## 建议的下一步

1. 引入 Flyway 或 Liquibase，把当前分散的 `*SchemaInitializer` 收敛为版本化迁移脚本。
2. 将教育表标记为 legacy，并在确认没有入口依赖后分阶段删除代码和表。
3. 增加管理员数据库健康页：展示各家族记录数、向量 READY/PENDING/FAILED 数、最近索引错误。
4. 给 RAG 建立分层索引策略：原始记录、摘要、核心记忆、时间淡化层分别索引，召回时只取授权且相关的片段。
5. 定期清理失败 embedding、孤立记录和过期授权，避免长期运行后数据变脏。
